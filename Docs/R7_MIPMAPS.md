# R7 画像のミップマップと、見た目の水準（標準見た目の最初の機能）

2026-11-22。DX12 の「標準見た目」の最初の機能として、画像のミップマップ（半分ずつに縮めた画像の列）を入れた。縮小して描いた画像のちらつき・縞の消失を直し、斜めから見た遠くの地面などを、なめらかにする。DxLib と同じ見た目にすることは目的にしない（[ロードマップの「完全互換」の判定](ROADMAP.md#完全互換の判定)）。公開 API は変わらない（画像を作る側が、ミップマップつきの作成を呼べるようになっただけ）。

## 見た目の水準（`ERenderLook`）

|水準|意味|
|---|---|
|`Compat`（互換見た目。**いまの既定**）|従来（DxLib）の式を再現する。命令の順序・状態・座標・深度・合成の意味を DxLib と画素で比べる検査は、この水準で行う|
|`Standard`（標準見た目）|DX12 が、DxLib では出せない綺麗な描画をする。画像のミップマップなど。R7b のルックデブで機能を増やす|

DX12 の起動オプション `--dx12-look=compat | standard`（大文字小文字は問わない。読めなければ警告を出して compat）で選ぶ。ログに `DX12 look: standard` と出る。DxLib・Null は、見た目の水準を持たず、いつも従来の見た目。**既定を Standard に替える**のは、標準見た目の機能が揃い、画素比較の検査が compat を明示して通るようになってから（R7b）。

## ミップマップ

- **作り方（`NTextureMips`。`Library/Core/Render/TextureMips.*`。GPU・API を知らない純粋な計算）**: 箱フィルターで、段 k の画素は、段 k - 1 の、重なる範囲の画素の面積の重みつきの平均。辺が奇数でも、端の画素を捨てず、面積で割る（5 画素 → 2 画素なら、真ん中の画素は両方に半分ずつ入る）。段の大きさは、元の辺を 2 で割った切り捨て（最小 1）で、1 x 1 まで作る（Direct3D のミップの規則と同じ）。
- **色は線形の光で平均する**: sRGB の値を線形の光へ戻して平均し、sRGB へ戻す。細かい白黒の格子を縮めると、値のまま平均した 128 ではなく、中間の明るさ 188 前後になる（画面に出る明るさとして、正しい）。1 色の画像は、全部の段で、まったく同じ色のまま（256 通りの灰色・アルファ 1〜255 を検査）。
- **透明な画素の色は混ぜない**: 色をアルファで重みづけ（乗算済み）して平均し、戻すときに割る。透明部分の色が、縁ににじまない。アルファは線形に平均。
- **線形データ画像**: `LoadTextureData` またはマテリアルの `TextureMipMode: LinearData` で指定する。RGBA の各成分を独立した線形値として面積平均し、アルファを RGB の重みに使わない。同じファイルでも色用とデータ用は別々に共有する。指定しなければ従来の色・透明度の処理を使う。これは縮小画像の生成方法の指定であり、シェーダーの色空間変換を指定するものではない。法線の平均値は生成時に正規化せず、読み取り側で扱う。法線の分散に応じた粗さの補正は未対応。参考: [Epic の Texture Asset Editor](https://dev.epicgames.com/documentation/unreal-engine/texture-asset-editor-in-unreal-engine)。
- **DX12 の画像（`CDX12TextureStore`）**: `CreateTextureRGBA8Mipped`（`IRenderTextureResources` の新しい窓口。既定は `CreateTextureRGBA8` と同じ）を標準見た目で呼ぶと、CPU で段を作り、全部の段を転送し（`GetCopyableFootprints` の段ごとの配置）、SRV に段の数を入れる。既存の描画の標本抽出（`DX12GeometryRenderer` の 160 通りのサンプラー）は、もともと `MaxLOD = 最大`・双線形のとき `MIN_MAG_MIP_LINEAR`・異方性のとき `ANISOTROPIC` なので、**段があるだけで、三線形・異方性の描画になる**（これまで異方性が「状態だけ」だった理由）。`UpdateTextureRGBA8` は、段を持つ画像なら、段も作り直す。
- **どの画像が段を持つか**: 画像のファイルから読んだ画像（`LoadTexture` / `CreateTextureFromMemory`）だけ。ピクセルから作る画像（動的な画像・生成した画像）・文字・描画先・compute 画像は、段なし（毎フレーム更新するものの費用と、文字を 1 対 1 で鮮明に見せるため）。16M 画素を超える画像も段なし（作る間の一時メモリのため）。メモリは約 1.33 倍。

## 検査

- **契約** `Source/SelfTest/RunTextureMipsTests.ps1`（37 件。Debug / Release。GPU は使わない）: 段の数と大きさ・1 色の画像がどの段でもそのまま・白黒の格子が 188 前後（線形の光）・透明な画素の色が混ざらない・アルファの重み・奇数の辺の面積の平均（横・縦）・勾配と 4 つの隅の向き・不正な入力（大きさ 0・画素なし・上限超え）の拒否と出力の保持・見た目の水準の名前の読み取り・線形データの独立した成分平均。
- **GPU で縮小して描いた絵** `CaptureContractMain.cpp` の `CheckMipmaps`（DX12・WARP）: 8 画素に 1 本の白い縦縞の 256 x 256 の画像を、32 x 32 に縮めて描く。**段なし（互換見た目）は、縞が全部抜けて真っ黒（平均 0）、段つき（標準見た目）は、線形の光の平均で、一様な 99**（白 1/8 の sRGB）。
- **変異検査** `RunTextureMipsMutationTests.ps1`（28 件。**すべて検出**。無限ループ 2 件・クラッシュ 2 件を含む）: 段の数、辺の最小値、線形化なし・指数の取り違え・戻し忘れ、アルファの乗算・割り戻し・アルファの平均、丸め、奇数の端の切り捨て・面積の重みなし（横・縦）、縦横の取り違え・転置・前の段の幅、上限・null の受け入れ、失敗で出力を変える、水準の名前（4 件）、データ画像への色用フィルターとアルファ重みの誤適用。**透明な画素のガードを外す変異は、等価**（アルファ 0 の割り戻しの NaN が 0 に丸められ、出力が同じ。検査には含めない）。GPU 側も、ビューが段の数を無視する変異と、水準の判定を外す変異を、手元で試して、どちらも `CheckMipmaps` が失敗することを確かめた。
- **全体検査**に、`texture mips contracts`（Debug / Release）と `texture mips mutations` の 3 手順を足した。

## 残り（R7b へ）

- **サンプルの絵の比べは、まだ compat**: DX12 の画像比較の検査（DxLib との比べ）は、既定の compat で動く。標準見た目を既定にするとき、検査へ `--dx12-look=compat` を渡す。
- **標準見た目の作り込み**: ミップマップだけでは、サンプルの見た目は、ほとんど変わらない（画像を縮小して描く場面が少ない）。HDR の場面・トーンマップ・影・環境光・アンチエイリアス・ポスト処理などを、同じ水準の切り替えの下へ足していく。
- **段を持たない画像**: 動的な画像・生成した画像・描画先を縮小して描くときの、ミップ生成（GPU）は、まだ。
- **異方性の確認**: 斜めから見た地面の画像で、異方性（`Anisotropy` の状態）が効いて鮮明になることの、絵での確認は、まだ（サンプラーは既にあり、段があれば効く）。
- **法線の分散と粗さ**: 線形平均した法線の長さが失われる場合の、縮小時の反射の補正を検討する。画像圧縮と品質段階も未対応。
