# R4 ライトカリング（タイルごとの光の一覧。Forward+ / Deferred+）

2026-11-21。R4 の「共通のクラスタ分割、ライト交差判定・一覧作成、上限超過の検出と欠落しない対処、両方式への接続、ライト数の表示」の最初の縦の経路を、公開のシェーダー窓口の上に作った。画面をタイルに分け、タイルごとに届く点光源の一覧を作り、シェーダーが画素の属するタイルの一覧だけを評価する。同じ一覧を、Forward（Forward+）でも Deferred（Deferred+）でも使うので、**Forward / Forward+ / Deferred / Deferred+ の 4 方式を、同じ入力で切り替えられる**。DxLib・DX12 のどちらでも、同じコードで動く。

## 構成

|配置|役割|
|---|---|
|`Library/Framework/Render/LightCulling/TileLightGrid.*`|`CTileLightGrid`: タイルごとの光の一覧を作る（CPU の基準実装）。`WriteImage` で 8 ビット RGBA の画像へ詰める|
|`Library/Framework/Render/LightCulling/LightCullingShaders.*`|`NLightCullingShaders`: 一覧を読む HLSL を文字列で渡す|
|`EngineContent/Shaders/LightCulling/TileLightList.hlsli`|一覧を読む部品（`TileOfPixel`・`IsTileOverflowed`・`LoadTileTexel`）|
|`Samples/Source/Deferred`・`Samples/Assets/Deferred`|サンプル `Deferred`: 動く光 64 個。キー 4 で、一覧を使う / 全部の光を評価する|

## 一覧の作り方

- **タイル**は、カメラから Far の面まで伸びる四角錐（既定は 32 ピクセル四方、画面の端のタイルは端まで）。4 つの側面は、`FGBufferView` と同じ「Far の面の画面の端の位置」から、カメラを通る面として作る（レンズのずらし・横の拡大も含む）。
- **光**は、半径 `Radius` の球。球が 4 つの側面の内側に少しでもかかり（`dot( 法線, 中心 ) >= -半径`）、カメラの前向きの奥行きで Near〜Far に重なるとき、そのタイルの一覧に入れる。見落とさない（球が触れるタイルには、必ず入る）が、四角錐の角の近くでは、触れていないタイルに入ることもある（保守的）。半径が 0 以下の光は、どのタイルにも入らない。
- **奥行きの範囲**は、画面の中の物の実際の奥行きでなく、Near から Far まで全部として扱う。遠くのタイル（地平線寄り）には、多くの光が入る。
- 一覧は**光の番号の昇順**。光の足し算の順が、全部の光を評価するときと同じになる。光の寄与は、半径の端で 0 なので、一覧に入らない光を飛ばしても、結果が**ビットまで一致**する。
- **上限と溢れ**: タイル 1 枚の一覧の上限 `MaxLightsPerTile`（既定 24、3 の倍数）を超える光が届くタイルは、「溢れた」印を付け、一覧は上限で打ち切る。シェーダーは、溢れたタイルでは全部の光を評価する（欠落させない）。`GetNumOverflowedTiles` で、溢れたタイルの数が分かる。

## 画像への詰め方

8 ビット RGBA の画像。幅 = タイルの列 x `TexelsPerTile`、高さ = タイルの行。タイル 1 枚が横に `MaxLightsPerTile / 3` 画素で、1 画素の R・G・B に、光の番号 + 1 を 1 つずつ詰める（0 は一覧の終わり）。溢れたタイルは、先頭の画素の R が 255（光の番号 + 1 は 254 まで。光は 254 個まで）。シェーダーは `Load` で 1 画素ずつ読む。`CDynamicTexture::Update` で、毎フレーム反映できる大きさ（サンプルは 40 x 20 タイルで 640 x 20）。

```cpp
CTileLightGrid Grid;
Grid.Build( Camera, FCameraViewport { 1280, 640 }, Lights, NumLights );   // Lights は FCullLight（位置と半径）
Grid.WriteImage( Image );                                                  // 同じ大きさなら、画素だけ書き換える
Texture->Update( Image );
```

```hlsl
#define TILE_LIGHTS_REGISTER t0      // 一覧の画像の段（部品の前に決める。G-buffer を読むシェーダーは t4）
// ...TileLightList.hlsli...
int2 tile = TileOfPixel( pixel, tileSize );     // pixel = SV_Position.xy
if ( !IsTileOverflowed( tile, texelsPerTile ) )
{
    for ( int texel = 0; texel < texelsPerTile; ++texel )
    {
        int3 ids = LoadTileTexel( tile, texelsPerTile, texel );   // 一覧の終わりは -1
        ...
    }
}
```

## 4 方式の比べ

サンプル `Deferred` は、Forward と Deferred で同じ光の式（`Lighting`）を使い、`Lighting` の動く光の足し算だけが、一覧（キー 4 で入り切り）を使う。画面の左上に、光の数・タイルの数・タイルごとの光の数の平均・溢れたタイルの数を出す。コマンドラインは、`--deferred-no-tiles`（全部の光）、`--deferred-tile-capacity=<3〜96>`（上限。小さくして溢れを起こす）、`--deferred-tile-stats`（統計をログへ。画面の文字は描かない）。

## 検査

- **契約** `Source/SelfTest/RunLightCullingTests.ps1`（Debug / Release）: 6 種類のカメラ（既定・向きと正方形・横の拡大・レンズのずらし・広角・狭い視野）で、散らばった光（カメラの後ろ・Far の先・視錐台の外を含む）を、タイルの中の点（4 隅・中心 x 6 つの奥行き）と全部の光の比べ（基準）で確かめて、**見落としが 0**（点と光の組 4,000〜70,000 件）。一覧の長さの合計は、全タイル x 全光の 5〜9%。昇順。近遠面（カメラの後ろ・Far の先・Far に触れる・Near をまたぐ）、カメラを含む球は全タイル、半径 0 以下はどこにも入らない、画面の中心の光は中心のタイル、溢れ（上限ちょうどは溢れない・超えると印を付けて打ち切る）、画像の詰め方（古い画素が残らない・大きさが違えば作り直す・一覧の復号が一致）、作れない入力（NaN・上限が 3 の倍数でない・タイルが小さすぎる・光が 254 個を超える・正射影・空の大きさ）の拒否と、失敗が前の中身を残さないこと。
- **HLSL の読み出しを WARP の D3D11 のコンピュートシェーダーで実際に走らせ**（`Source/SelfTest/LightCullingContract.hlsl`）、溢れの印・画素ごとの光の番号（一覧の終わりの -1 を含む）・画素からタイルへの対応を、C++ の一覧と比べる。
- **画像の比べ** `RunDeferredTests.ps1 -Platform`: DX12・WARP・DxLib の 3 つの実行先で、Forward と Deferred それぞれについて、一覧を使った絵と全部の光を評価した絵（基準）の全画素を比べる。**差が 0**（Forward+・Deferred+ とも）。一覧の長さの平均が 20 より短いこと（光は 64 個。実測 14.8）と、基準の実行が一覧を使っていないことを、ログの統計で確かめる。上限を 3 に絞って溢れたタイル（673 枚）が全部の光の評価に切り替わっても、同じ絵になる。半透明のガラスも、同じ一覧で描く。
- **変異検査**: 下の「変異検査の結果」。C++ 側の 12 件は `RunLightCullingMutationTests.ps1` として、`RunAllChecks.ps1` に登録している。

## 変異検査の結果

契約の実行ファイルは `x64/<構成>/mazigatiDX.lib` にリンクし、HLSL はライブラリへ埋め込まれるので、HLSL の変異は、変異ごとにライブラリを作り直して確かめた。

- **C++（`TileLightGrid.cpp`）12 件**: 球と側面の比べで半径を無視する・半分にする、Far・Near の判定を外す、半径 0 以下を受け入れる、側面の法線の向きを逆にする、タイルの角を取り違える、溢れの判定を 1 つ遅らせる・印を付けない、タイルの行の数を切り捨てる、画像の溢れの印の値・光の番号の足し算の誤り。**12 件すべて検出**。
- **HLSL（`TileLightList.hlsli`）6 件**: 溢れの印の値、光の番号から 1 を引かない、8 ビットの値から戻す倍率（255 → 254）、画素の横の位置にタイル内の画素の番号を足さない、画素からタイルへの対応（タイルの大きさ）、行の座標を列にする。**6 件すべて検出**。倍率の変異は、最初の契約（光 70 個）では生き残った（番号が 127 以下なら四捨五入で同じ値になる）ので、光を 250 個（番号 200 超）にした読み出しの検査を足して、検出できるようにした。
- **画像でだけ見つかる、サンプルの HLSL 4 件**（溢れたタイルの判定を外す・2 つ目の光を 1 つ目と取り違える・3 つ目の光を足さない・タイルの大きさを倍にする）。実行先を DX12 に絞った絵の比べ（`-Platform -Modes dx12`）で、**4 件すべて検出**。

## 現在の範囲

- 一覧は **CPU が作る**。R4 の「GPU のライト交差判定・一覧作成」（DX12 の compute）は、まだ。DxLib にも使える、移植しやすい基準実装と、その検査が先に入った。compute 版ができたら、この実装を基準に画素・一覧を比べる。
- タイルは **2 次元**（画面の分割）で、奥行きは分けない（クラスタ分割ではない）。タイルごとの奥行きの範囲（G-buffer の最小・最大の深度）も使わない。地平線寄りのタイルは、多くの光が入って溢れやすい（サンプルの既定の上限 48 では、溢れは 0。24 では 62 枚）。
- 点光源だけ。スポットライトと、光の範囲を描く方式（Deferred の光の体積）は、まだ。
- 光は 254 個まで。光の数と一覧の統計は画面に出すが、GPU の時間の表示は、まだ。
