# R4 ライトカリング（タイルごとの光の一覧。Forward+ / Deferred+）

2026-11-21。R4 の「共通のクラスタ分割、ライト交差判定・一覧作成、上限超過の検出と欠落しない対処、両方式への接続、ライト数の表示」の最初の縦の経路を、公開のシェーダー窓口の上に作った。画面をタイルに、さらに奥行きを層に分け（クラスタ = タイル x 層）、クラスタごとに届く光源（点光源・スポットライト）の一覧を作り、シェーダーが画素の属するクラスタの一覧だけを評価する（奥行きを分けない 1 層は、タイルだけの分割）。同じ一覧を、Forward（Forward+）でも Deferred（Deferred+）でも使うので、**Forward / Forward+ / Deferred / Deferred+ の 4 方式を、同じ入力で切り替えられる**。DxLib・DX12 のどちらでも、同じコードで動く。

## 一覧の作り方

- **タイル**は、カメラから Far の面まで伸びる四角錐（既定は 32 ピクセル四方、画面の端のタイルは端まで）。4 つの側面は、`FGBufferView` と同じ「Far の面の画面の端の位置」から、カメラを通る面として作る（レンズのずらし・横の拡大も含む）。
- **点の光**は、半径 `Radius` の球。球が 4 つの側面の内側に少しでもかかり（`dot( 法線, 中心 ) >= -半径`）、カメラの前向きの奥行きで Near〜Far に重なるとき、そのタイルの一覧に入れる。見落とさない（球が触れるタイルには、必ず入る）が、四角錐の角の近くでは、触れていないタイルに入ることもある（保守的）。半径が 0 以下の光は、どのタイルにも入らない。
- **奥行きの層**（`FTileLightGridDesc::NumDepthSlices`、既定 1 = 分けない）: Near から Far までを、奥行き（カメラの前向きの距離）の比が等しい（対数の）層に分ける。層 k の始まりは `Near x (Far / Near)^(k / 層の数)`。光は、球の奥行きの範囲（中心の奥行き ± 半径）が重なる層にだけ入る。画素の層は、画素の奥行きから `GetSliceOfDepth`（シェーダーの `SliceOfDepth` と同じ式 `floor( log( 奥行き / Near ) x 層の数 / log( Far / Near ) )`）で決まる。Near より手前は最初の層、Far より奥は最後の層。**層の範囲は、前後に 0.1%（`SliceMargin`）広げる**: GPU の対数の丸めで、画素が隣の層に入っても、光が欠落しない（C++ と HLSL の層の番号は、境目の相対 1e-4 より近い所だけ、1 つのずれを許す。それ以外は同じ）。奥行きを分けないときは、奥行きの範囲を Near から Far まで全部として扱う（遠くのタイルに多くの光が入る）。層に分けると、遠くのクラスタの光が、その奥行きの光だけになる。
- **スポットライト**（`FCullLight::Direction`・`ConeHalfAngle`。半角が π 未満の光）: 光が届く範囲は、`Radius` の球を、軸（`Direction`）から半角以内の円錐で切り取った扇形（頂点が光の位置）。側面・奥行きとの比べは、球の半径の代わりに、**範囲が、面の法線の向きへ、光の位置からどこまで広がるか**を使う。法線が円錐の軸から半角以内なら半径、外なら、円錐の縁の向きへの広がり `半径 x cos( 軸との角 - 半角 )`、それが負なら頂点（0）。これは、扇形の中の点の、その向きへの距離の最大値そのものなので、球で包むより絞れて、見落とさない。奥行きの範囲も同じ式（前向きと後ろ向き）で決めるので、奥へ向くスポットライトは、頂点より手前の層に入らない。点の光は、どの向きも半径なので、球のときと同じ結果。半角 π 以上は点の光、0 以下はどこにも入らない。向きの長さは問わない（長さ 0・有限でない向きは、一覧が作れない）。サンプルの 16 層で、同じ光を点の光として入れたときより、一覧の平均が 2〜4 割短い（検査の乱数の光で）。`FCullLight::FromLight( FLight )` で、既存の点・スポットライトから作れる（`FLight` の角度は全角なので、半分にする。方向ライトは、位置で絞れないので作れない）。
- 一覧は**光の番号の昇順**。光の足し算の順が、全部の光を評価するときと同じになる。光の寄与は、半径の端で 0 なので、一覧に入らない光を飛ばしても、結果が**ビットまで一致**する。
- **上限と溢れ**: クラスタ 1 つの一覧の上限 `MaxLightsPerTile`（既定 24、3 の倍数）を超える光が届くクラスタは、「溢れた」印を付け、一覧は上限で打ち切る。シェーダーは、溢れたクラスタでは全部の光を評価する（欠落させない）。`GetNumOverflowedTiles` で、溢れたクラスタの数が分かる。

## 画像への詰め方

8 ビット RGBA の画像。幅 = タイルの列 x `TexelsPerTile`、高さ = 層の数 x タイルの行（行 = 層 x タイルの行の数 + タイルの行）。クラスタ 1 つが横に `MaxLightsPerTile / 3` 画素で、1 画素の R・G・B に、光の番号 + 1 を 1 つずつ詰める（0 は一覧の終わり）。溢れたクラスタは、先頭の画素の R が 255（光の番号 + 1 は 254 まで。光は 254 個まで）。シェーダーは `Load` で 1 画素ずつ読む。`CDynamicTexture::Update` で、毎フレーム反映できる大きさ（サンプルは 40 x 20 タイル x 16 層で、上限 36 のとき 480 x 320。毎フレーム約 600KB）。

```cpp
CTileLightGrid Grid;
FTileLightGridDesc Desc;
Desc.NumDepthSlices = 16;                                                  // 奥行きを 16 層に分ける（1 なら、タイルだけ）
Grid.Build( Camera, FCameraViewport { 1280, 640 }, Lights, NumLights, Desc );   // Lights は FCullLight（位置・半径。スポットライトは、さらに向きと円錐の半角）
Grid.WriteImage( Image );                                                  // 同じ大きさなら、画素だけ書き換える
Texture->Update( Image );
```

```hlsl
#define TILE_LIGHTS_REGISTER t0      // 一覧の画像の段（部品の前に決める。G-buffer を読むシェーダーは t4）

// pixel = SV_Position.xy、depth = 画素の奥行き（カメラの前向きの距離）。奥行きを分けないなら、numSlices = 1

        ...
```

## GPU での一覧作成（`CTileLightBuilder`）

CPU の `CTileLightGrid`（基準実装）と同じ判定を、ピクセルシェーダーで行って、同じ形式の一覧の画像を GPU で作る。新しい compute の窓口は要らず、公開のシェーダー窓口（`ShaderRect`・`ShaderConstants`・描画先）だけで動くので、**DxLib でも DX12 でも、同じコードで動く**。

- **仕組み**: 一覧の画像（8 ビット RGBA。幅 = タイルの列 x クラスタ 1 つの画素数、高さ = 層の数 x タイルの行）の描画先を、`ShaderRect` で全体塗る。画素 1 つが、1 つのクラスタの 3 つの光の番号を、全部の光との交差判定で数えて決める（`BuildTileLightTexel`）: 画素の座標からクラスタ（タイルの列・行・層）を求め、タイルの 4 つの側面と層の奥行きの範囲を作り、光を番号の昇順に調べて、届く光を数え、自分が受け持つ 3 つ（画素の番号 x 3 番目から）の番号を書く。上限を超えたら、先頭の画素に溢れの印（255）を書く。判定は CPU と同じ式（`GetExtent` を含む）で、浮動小数点の丸めで境目の光を落とさないよう、各比べに、ごく小さな余裕（光の距離の 1e-5 倍）を足す。したがって GPU の一覧は、CPU の一覧と同じか、境目で、ほんの少し多い（足りなくならない）。
- **定数**: 1 つの定数バッファは 4096 バイトまでなので、3 つに分ける（b4: カメラ・クラスタの分け方、b5: 光の位置と半径（254 個）、b6: スポットライトの軸と半角の cos）。`FTileLightBuildData` が、HLSL の cbuffer と同じ並び（WARP の検査は、この構造体のメモリをそのまま定数にするので、並びの取り違えも見つかる）。光は 254 個まで（CPU と同じ）。
- **使い方**: `CTileLightBuilder::Create`（シェーダーのコンパイルと描画先。メインスレッド）、毎フレーム、場面を描く前に `Record( CommandList, Camera, Lights, NumLights )`、読むシェーダーの段へ `GetTexture()` を `ShaderTexture` で置く。**描画の状態（深度・合成・補間）は変えない**（最初の実装は、描画先の中で深度の判定を切って、戻さなかった。続く場面の描画の深度判定が切れて、遮蔽が崩れた。`ShaderRect` は深度を使わず、シェーダーは画像を読まず、出力のアルファは 1 なので、呼び出し側の状態のままで正しく書ける）。
- **サンプル**: `Deferred` は、既定で GPU で一覧を作る（画面に "built on the GPU"）。`--deferred-cpu-lights` で、CPU で作った一覧（動的な画像）を使う。CPU の一覧は、統計のために、どちらの経路でも毎フレーム作る。
- **費用**: 画素 1 つが全部の光を調べる（クラスタの画素数 x 光の数）。サンプルは 480 x 320 画素 x 64 個の光で、GPU には軽い。光が数百になる、またはクラスタが非常に多い場合は、タイルごとの粗い絞りや compute 版が必要（R9）。

## 4 方式の比べ

サンプル `Deferred` は、Forward と Deferred で同じ光の式（`Lighting`）を使い、`Lighting` の動く光の足し算だけが、一覧（キー 4 で入り切り）を使う。画面の左上に、光の数（うちスポットライト）・タイルの数・層の数・クラスタごとの光の数の平均・溢れたクラスタの数を出す。コマンドラインは、`--deferred-no-tiles`（全部の光）、`--deferred-no-spots`（スポットライトを消す）、`--deferred-slices=<1〜64>`（奥行きの層の数。既定 16。1 でタイルだけ）、`--deferred-tile-capacity=<3〜96>`（上限。既定 36。小さくして溢れを起こす）、`--deferred-tile-stats`（統計をログへ。画面の文字は描かない）。サンプルの 64 個の光（点 46・スポットライト 18）の、クラスタごとの一覧の長さの平均は、タイルだけで 17.0、16 層で 3.6（既定の上限 36 で、溢れは 0）。スポットライトは遠くまで届くので、点の光だけのときの上限 24 では、16 層で 150 クラスタが溢れる（溢れても、全部の光を評価するので、絵は同じ）。

- **契約** `Source/SelfTest/RunLightCullingTests.ps1`（Debug / Release。346 件）: 6 種類のカメラ（既定・向きと正方形・横の拡大・レンズのずらし・広角・狭い視野）で、散らばった光（カメラの後ろ・Far の先・視錐台の外を含む）を、タイルの中の点（4 隅・中心 x 6 つの奥行き）と全部の光の比べ（基準）で確かめて、**見落としが 0**（点と光の組 4,000〜70,000 件）。一覧の長さの合計は、全タイル x 全光の 5〜9%。昇順。近遠面（カメラの後ろ・Far の先・Far に触れる・Near をまたぐ）、カメラを含む球は全タイル、半径 0 以下はどこにも入らない、画面の中心の光は中心のタイル、溢れ（上限ちょうどは溢れない・超えると印を付けて打ち切る）、画像の詰め方（古い画素が残らない・大きさが違えば作り直す・一覧の復号が一致）、作れない入力（NaN・上限が 3 の倍数でない・タイルが小さすぎる・光が 254 個を超える・正射影・空の大きさ）の拒否と、失敗が前の中身を残さないこと。

- **画像の比べ** `RunDeferredTests.ps1 -Platform`: DX12・WARP・DxLib の 3 つの実行先で、Forward と Deferred それぞれについて、一覧を使った絵と全部の光を評価した絵（基準）の全画素を比べる。**差が 0**（Forward+・Deferred+ とも。16 層と、層に分けない 1 層の両方）。一覧の長さの平均が 20 より短いこと（光は 64 個。1 層で 17.0、16 層で 3.6）、16 層が 1 層より 1.5 倍以上短いこと、基準の実行が一覧を使っていないことを、ログの統計で確かめる。上限を 3 に絞って溢れたクラスタ（16 層で 3,636 枚、1 層で 666 枚）が全部の光の評価に切り替わっても、同じ絵になる。半透明のガラスも、同じ一覧で描く。GPU で作った一覧の絵（既定）に加えて、CPU で作った一覧の絵（`--deferred-cpu-lights`）も、全部の光を評価した絵と全画素一致する（GPU 側と基準が、同じ誤りで一致してしまう — 例えば描画の状態を乱す — ことを、CPU の経路との比べで防ぐ）。さらに、スポットライトを消した絵（`--deferred-no-spots`）が、全部の光を評価した絵と、約 21 万ピクセル（全体の 26%）違うこと（5 万以上）を確かめて、スポットライトが絵に効いていることを保証する（一覧の比べは、同じ式どうしの比べなので、スポットライトが全部消えても一致してしまう）。
- **GPU の一覧作成の検査**: HLSL の `BuildTileLightTexel` を、WARP の D3D11 コンピュートシェーダー（`BuildMain`）で走らせ、C++ の一覧と画素ごとに比べる。3 種類のカメラ（既定・向きと正方形・広角）x 点の光（1 層・12 層）・スポットライト（1 層・12 層）・上限を絞って溢れさせる 2 通り。**どのクラスタも CPU と同じ一覧**（足りない光 0・余分な光 0・溢れの有無も一致。上限 3 で 1,626 クラスタが溢れる場合も一致）、光の番号は昇順で一覧の終わりの後ろは 0。使えない光（半径 0 以下・半角 0 のスポットライト）と、層の境目のすぐ内側の光（層の範囲を広げた分）も混ぜる。HLSL は、ライブラリへ埋め込んだ正本をそのまま使う（変異検査は、壊した HLSL を契約の 2 つ目の引数で渡して、ライブラリを作り直さずに試す）。

## 変異検査の結果

## 現在の範囲

- 一覧は、**CPU（`CTileLightGrid`。基準実装）でも、GPU（`CTileLightBuilder`。ピクセルシェーダー。サンプルの既定）でも作れる**。GPU の compute シェーダー版（公開の compute の窓口が要る）は、まだ。compute 版ができたら、CPU の実装と、ピクセルシェーダー版を基準に、一覧を比べる。
- クラスタは、タイル x 奥行きの層（対数の分け方）で、層の数は起動のときに決める（一覧の画像の大きさが変わる）。クラスタごとの奥行きの範囲（G-buffer の最小・最大の深度）は使わない（層の範囲は Near〜Far を分けたものだけ）。奥行きを分けない 1 層では、遠くのタイルが多くの光で溢れやすい（サンプルで、上限 24 は 62 枚溢れる）が、16 層では、上限 24 で溢れは 0。
- 点光源とスポットライト（円錐の扇形）。光の範囲を描く方式（Deferred の光の体積）は、まだ。スポットライトの影・光の強さの式は、R7（サンプルのスポットライトは、サンプル専用の式で、円錐の縁で 0 になるように滑らかに弱める）。
