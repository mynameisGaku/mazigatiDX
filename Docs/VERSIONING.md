# バージョン方針

mazigatiDX の版の付け方と、互換の約束、対象環境、ブランチの運用です。

## 版の付け方

[セマンティック バージョニング](https://semver.org/lang/ja/)（`メジャー.マイナー.パッチ`）に従います。現在の版は `Library/Core/Version.h`（`NVersion`）にあり、起動ログとクラッシュ報告に出ます。版を上げるときは、`Version.h` と [CHANGELOG.md](../CHANGELOG.md) を同時に直し、同じ版のタグ（`v0.9.0` のように）を付けます。

|版|意味|
|---|---|
|`0.x.y`（v1.0.0 より前）|公開前の版。公開した窓口でも、壊す変更が入ることがある（そのときは、マイナーを上げ、変更履歴に「壊す変更」として書く）|
|`1.0.0`|最初の安定版。このあとは、下の互換の約束を守る|
|メジャー|互換を壊す変更（約束している範囲の API の削除・意味の変更）|
|マイナー|互換を保つ機能の追加|
|パッチ|互換を保つ修正|

## 互換を約束する範囲（v1.0.0 から）

約束するのは、次の 2 つです。

- `Library/Core/Interfaces` の窓口（`I...` のインターフェースと、その引数・戻り値の値の型）。
- [開発手順](DEVELOPMENT.md)に使い方を書いた、`Library/Framework` の公開ヘッダー。

次は約束しません（内部の扱い。いつでも変わります）。

- `Library/Platform/*`（DxLib などの実装。バックエンドを替えられるようにするため）。
- `Library/DebugUI`、`Editor`、`Samples`（エディタ、サンプルのコード）。
- ファイル名や名前空間が `Detail`・`Internal` を含むもの、開発手順に書いていないもの。
- アセットの形式（`.gxsprite` など）は、版を上げるときに読み込み側が古い形式を読めるようにします（移行の手順を変更履歴に書きます）。

## 壊す変更の扱い

1. 約束している範囲の API を壊すときは、まず新しい API を足し、古い API に「非推奨」の印を付けて、次のマイナーまで残します（0.x の間は、残さないこともあります）。
2. 消すのは、次のメジャーです。
3. 壊す変更は、必ず [CHANGELOG.md](../CHANGELOG.md) の「壊す変更」に、置き換え方と一緒に書きます。

## 対象環境

v1.0.0 の対象は、Windows 10 / 11（64 ビット）と、Visual Studio（MSVC ツールセット v145）です。ほかの OS は、将来の目標です（v1.0.0 の約束には含みません）。DxLib に触れる部分を `Library/Platform/DxLib` に閉じ込めているのは、描画や OS の層を替えられるようにするためです。

## ブランチとタグ

|名前|役割|
|---|---|
|`main`|検証を終えた安定版。リリースのタグは、ここに付ける|
|`dev`|全機能を統合して確認する開発版|
|`Effect`・`Asset`・`Core` など|責務ごとの機能ブランチ。確認を揃えてから `dev` へ統合する|

リリースの手順: 1. `dev` で [すべての検査](DEVELOPMENT.md)（`Tools/RunAllChecks.ps1`）と、まっさらな環境での確認（`Tools/VerifyCleanBuild.ps1`）を通す。 2. `Version.h` と変更履歴を直す。 3. `main` へ反映して、タグ `vX.Y.Z` を付ける。
